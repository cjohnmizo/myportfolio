# Portfolio Architecture

## Goal

Build a polished, backend-free developer portfolio for `cjohnmizo.in` using Next.js App Router, TypeScript, Tailwind CSS, local content, and Vercel.

## Application Layers

### Presentation

- `src/app/(public)` contains the public portfolio routes.
- `src/components/ui` contains reusable design-system primitives.
- `src/components/portfolio` contains portfolio-specific composition.

### Domain and Data

- `src/types/portfolio.ts` defines strongly typed portfolio domain objects.
- `src/lib/portfolio/seeds.ts` is the canonical content source.
- `src/lib/portfolio/repository.ts` prepares sorted, published portfolio snapshots from local seed data.
- `src/lib/portfolio/project-presentation.ts` contains project display helpers.

### Infrastructure

- The app has no database, auth provider, storage backend, or CMS runtime.
- Project and brand assets live in `public/`.
- Health, sitemap, robots, manifest, Open Graph, and Twitter image routes are generated by Next.js.

## Runtime Model

- Public routes render from static local content.
- Content updates are code/content changes committed to the repository.
- Deployment is handled by Vercel.

## Visual System

- The portfolio uses a restrained navy and steel-blue portfolio direction with glass surfaces, clear cards, and lightweight motion.
- Global tokens live in `src/app/globals.css`.
- Shared surface styling comes from `glass-panel`, `surface-card`, and the UI primitives.

## SEO Strategy

- Route-level metadata for public pages and case studies.
- Static sitemap entries generated from local project data.
- Semantic sections, strong headings, and project-focused copy structure.

## Notes

- Keeping the portfolio backend-free reduces maintenance and deployment risk.
- The public site remains easy to update because content is centralized in typed seed data.
